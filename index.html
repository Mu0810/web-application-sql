Module 01

Introduction to SQL, Data Stores & Injection Attacks

Understanding how SQL and data stores work in web servers, and introduction to data store attacking with practical examples.

📚 What is a Data Store?

A data store is a repository for persistently storing and managing collections of data. This includes not just databases, but also simpler store types such as files, emails, etc. A database is a series of bytes managed by a DBMS, while a file is managed by a file system. Any database or file that is stored is called a data store.

The most common data stores are SQL databases, XML-based repositories, and LDAP directories.

⚡ How Injection Attacks Work

Injection flaws allow attackers to relay malicious code through an application to another system. These attacks include calls to the OS via system calls, use of external programs via shell commands, and calls to backend databases via SQL.

Any time an application uses an interpreter of any type, there is a danger of introducing an injection vulnerability. The web application functions as a discretionary access control to the data store, constructing queries based on the user's account and type.

🔒 SQL Injection - Login Bypass

Many applications use a database to validate login attempts with a simple query:

SQL - Original Query 
SELECT * FROM users WHERE username = 'marcus' AND password = 'secret'

An attacker who knows the admin username can bypass authentication:

SQL - Injection Payload (Username field) 
admin'--
SQL - Resulting Query 
SELECT * FROM users WHERE username = 'admin'--' AND password = 'random-pass'
-- The comment sequence (--) causes the password check to be ignored
-- Effective query: SELECT * FROM users WHERE username = 'admin'

⚠ Unknown Admin Username Attack

If the attacker doesn't know the admin username, they can log in as the first user in the database:

Payload: Username field 
' OR 1=1--
Resulting Query 
SELECT * FROM users WHERE username = '' OR 1=1--' AND password = 'random'
-- Returns ALL users. Application typically processes the first result (admin).

💡 XML Injection (XXE)

XML External Entity injection exploits standard XML parsing libraries that support entity references. Attackers can define external entities using the SYSTEM keyword to read local files or make network requests.

XXE - Reading Server Files 
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///windows/win.ini" > ]>
<Search><SearchTerm>&xxe;</SearchTerm></Search>
XXE - Internal Network Scanning 
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "http://192.168.1.1:25" > ]>
<Search><SearchTerm>&xxe;</SearchTerm></Search>
<!-- Can interact with internal network services unreachable from Internet -->
XXE Attack Capabilities:
  • Use application as proxy to retrieve internal content
  • Exploit vulnerabilities on back-end web applications
  • Port scanning on back-end systems
  • Denial of service via infinite file stream (e.g., /dev/random)

⚙ JavaScript Injection (SSJI)

Server-Side JavaScript Injection occurs when applications use the eval() function to process user input. Unlike client-side XSS, SSJI provides direct server access without social engineering.

Vulnerable Node.js Code 
var http = require('http');
http.createServer(function (request, response) {
  if (request.method === 'POST') {
    var data = '';
    request.addListener('data', function(chunk) { data += chunk; });
    request.addListener('end', function() {
      var bankData = eval("(" + data + ")");  // VULNERABLE!
      bankQuery(bankData.balance);
    });
  }
});
SSJI Payloads 
// Read directory contents
response.end(require('fs').readdirSync('.').toString())

// Execute system commands
require('child_process').spawn(filename);

// Write/overwrite files
require('fs').writeFileSync(path, content);
SECURE Fix - Use JSON.parse() 
var bankData = JSON.parse(data);  // Safe - cannot execute code
bankQuery(bankData.balance);

🔗 SQL Injection - Different Statement Types

Used to retrieve information. Entry point is usually the WHERE clause. The comment symbol can truncate the remainder of the query.

SELECT Injection
-- Search term: Wiley' OR 1=1--
SELECT author,title,year FROM books WHERE publisher = 'Wiley' OR 1=1--' and published=1
-- Returns ALL books, bypassing the published=1 filter

Used to create new rows. Common in registration forms. Attacker must ensure correct column count and types.

INSERT Injection
-- Original: INSERT INTO users (username, password, ID, privs) VALUES ('input', 'pass', 2248, 1)
-- Injecting into username field: hak', 'in9', 9999, 0)--
-- Result: Creates admin account with ID=9999 and privs=0 (admin)

Used to modify existing data. Common in password change functions.

UPDATE Injection
-- Original: UPDATE users SET password='new' WHERE user = 'marcus' AND password = 'old'
-- Injecting username: admin'--
-- Result: Changes admin password without knowing the old one

Used to delete rows. Subverting the WHERE clause can have catastrophic effects.

DELETE Caution
-- Modifying a DELETE WHERE clause can delete ALL rows
-- Same caution as UPDATE - subverting WHERE is devastating
-- Always use extreme caution with DELETE injection

∪ UNION operator & structural matching

01

Match column count

UNION combines result sets only when each SELECT returns the same number of columns. In an authorized lab, testers commonly use NULL placeholders because NULL is compatible with many data types.

02

Match data types

Corresponding fields must be identical or implicitly convertible. A string placed where the original query expects a number produces a useful structural error.

03

Locate display fields

Once structure is understood, identify which returned string field is rendered by the application. That field explains how unintended data could become visible.

Conceptual UNION shape
SELECT author, title, year FROM books WHERE publisher = ?
UNION SELECT NULL, 'lab-marker', NULL
-- Same column count; a harmless marker reveals the displayed text field.

≠ Filters are not a primary defense

Why blacklists fail

Blocking quotes, comments, spaces, or keywords does not fix query construction. Numeric contexts may need no quotes; balanced expressions may need no comment; case variants, encodings, whitespace, inline comments, character functions, and concatenation can change representation without changing meaning.

What to learn defensively

Normalize input once, validate against an allowlist, and keep values separate from query structure with parameterized APIs. A filter can be a supporting control, never the trust boundary.

↻ Second-order injection

A

Input arrives and is escaped before storage.

B

The stored value later appears trusted.

C

A second feature concatenates it into a new query.

D

The dormant structure is interpreted.

This flaw is hard to discover because submission and execution happen in different requests. Review every place stored data is later reused—profile display, password change, admin tools, batch jobs, exports, and integrations. Parameterize at every query boundary, including “internal” data.

◌ When results are not returned

Out-of-band

Historically, DBMS network features were abused to send query results through another channel. From a defense perspective, block unnecessary database egress and remove network-capable packages from low-privilege accounts.

Numeric channel

SUBSTRING/SUBSTR isolates a character and ASCII converts it to a number. An application that reveals only a numeric identifier can still become an unintended data channel.

Boolean channel

True and false conditions produce different pages, row counts, login outcomes, errors, or status codes. Repeated questions can infer hidden values one character—or bit—at a time.

Timing channel

A conditionally delayed response can signal true or false when content is identical. Delay mechanisms vary by DBMS, making timing both a fingerprint and a blind inference technique.

◐ Blind and time-based inference

TRUENormal responseExpected page, row, or login path
FALSEChanged responseBlank page, error, status, or measurable delay

Blind injection is present when attacker-controlled query logic changes an observable behavior even though query output is hidden. Boolean tests compare a known-true condition with a known-false condition. Conditional errors can provide the same signal. Time-based techniques replace page differences with response latency.

EngineHistorical delay familyDefensive detection
MySQLSLEEP, processor-heavy expressionsRepeated latency spikes tied to input shape
SQL ServerWAITFOR DELAY/TIMEWAITFOR in query telemetry; slow request clusters
OracleNetwork timeout / heavy-query techniquesUnexpected outbound attempts and long-running statements
Efficiency insight

Character-by-character testing can be reduced using ranges or bitwise questions. For defenders, this means low-volume, repetitive requests—not just obvious payloads—deserve correlation.

▤ From database access to file-system risk

The course compares MySQL file functions and SQL Server bulk/extended capabilities. Whether read or write access exists depends on engine, operating system, service identity, feature configuration, query batching, target path, and database privileges.

01DB data onlyRestricted account and no file APIs
02Read filesFile/bulk privileges expose host data
03Write filesOutput features cross the boundary
04OS commandsDangerous extensions magnify impact
Break the chainDisable unused file/network/command features · run the DBMS as a restricted OS account · separate read and write identities · constrain egress · monitor bulk operations · never grant application accounts server-control privileges.
Module 03

Encoding, Automation, XPath & LDAP

How representation changes affect weak filters, how authorized testing tools assist analysis, and how injection concepts reappear in XML and directory query languages.

⌘ Encoding & evasion taxonomy

%

URL encoding

Percent plus a hexadecimal byte. Common examples include space, percent, newline, and null representations.

A

Character functions

Database character functions can construct text from numeric character codes without literal quotes.

0x

Hex encoding

Some engines accept hexadecimal text directly or through conversion functions.

/**/

Comments & whitespace

Inline comments, tabs, and newlines may separate tokens or change how naïve filters see a statement.

∥

Concatenation

Breaking tokens or strings into pieces can preserve interpreter meaning while changing surface text.

≡

Equivalent logic

Many expressions are logically equivalent. Signature matching cannot enumerate every valid form.

Canonicalize firstDecode and normalize into one predictable representation before validation. Reject ambiguous or repeatedly encoded input. Then parameterize—the filter is not the fix.

⚙ Automation in an authorized lab

OPEN SOURCE

sqlmap

Automates detection, DBMS fingerprinting, data enumeration, and supported post-exploitation checks. Its large switch set can target a URL and session cookie, report the current DB/user, enumerate databases, tables, and columns, and selectively export authorized test data.

Best used after understanding the parameter and with a test scope. Results can be wrong or destructive; keep snapshots and backups.
SQL SERVER FOCUSED

SQLninja

A historic SQL Server-oriented tool with test, fingerprinting, escalation, upload, shell, and tunneling modes. The course emphasizes that automation is not a magic vulnerability finder and often needs manual context.

Modern defensive lesson: alert on database-to-OS transitions, unusual delay statements, outbound channels, and extended procedure use.

Application resultmatched nodes

XPath addresses nodes in XML and is case-sensitive. If an application concatenates credentials or search input into an XPath expression, crafted Boolean logic can change which nodes match. Unlike SQL, XPath has no universal comment token, so expressions are often balanced with Boolean structure.

Booleanization

Compare known-true and known-false predicates. If application behavior differs, functions such as substring() and string-length() can test one property at a time.

XML crawling

count(), node positions, child-node selection, and string length can map an unknown document. The request volume is high, which makes automation and anomaly detection relevant.

⌂ LDAP injection

LDAP powers directories such as Active Directory and OpenLDAP. Filters combine simple matches, disjunctions (any condition), conjunctions (all conditions), and wildcards. Unsafe concatenation may broaden a directory search or weaken application access control.

Simple(username=thomas)
OR / disjunctive(|(cn=term)(sn=term))
AND / conjunctive(&(username=thomas)(password=value))
Risk tokens( ) ; , * | & = NUL

LDAP exploitation is often blind: requested attributes are usually hard-coded and errors are sparse. Historic issues include wildcard broadening, batched filters, and NUL truncation. Defend with RFC-appropriate escaping APIs, allowlisted attribute values, fixed filter structure, and least-privileged bind accounts.

Module 04

Secure Every Data Store

NoSQL query safety, positive validation, contextual encoding, parameterized APIs, least privilege, canonicalization, and careful handling of sensitive data.

{ } NoSQL injection

NoSQL is an umbrella for stores using key/value, document, graph, XPath-like, or programming-language query models. Different engines have different security semantics; “not SQL” does not mean “not injectable.”

Unsafe object construction
db.users.find({
  username: req.body.username,
  password: req.body.password
});
Validate shape and type
const { username, password } = req.body;
if (typeof username !== 'string' ||
    typeof password !== 'string') reject();
// Use a restricted, typed query API.

If deserialized fields can be objects, attacker-controlled query operators may replace expected strings. Form parsers can also turn bracket notation into nested objects. Reject unknown keys, enforce primitive types, disable server-side scripting, and never pass request objects directly to a datastore API.

✓ The secure query pipeline

01CanonicalizeDecode once; normalize Unicode; reject ambiguous forms
→
02AllowlistType, length, range, format, known values
→
03ParameterizeBind every value; keep structure fixed
→
04AuthorizeCheck object and action, not just query validity
→
05EncodeApply context-specific output handling

Positive vs. negative validation

Allowlisting accepts only known-good type, size, range, format, and content. Blacklisting rejects known-bad patterns and is inherently incomplete. Use it only as an additional signal, never alone.

Output encoding

Encoding is context-specific: database values, HTML, URLs, logs, and command arguments have different rules. Escaping dynamic SQL is error-prone; prefer prepared statements.

? Prepared statements: structure first, values second

Vulnerable concatenation
const sql = "SELECT * FROM users " +
  "WHERE username='" + username + "' " +
  "AND password='" + password + "'";
Parameterized query
const sql = `SELECT * FROM users
             WHERE username = ?
             AND password_hash = ?`;
connection.execute(sql, [username, hash]);
Important limits

Bind every value in every query, including second-order data. Placeholders generally cannot represent table names, column names, sort direction, or other structural keywords—map those choices from fixed allowlists.

◇ Least privilege & sensitive data

Separate identities

Use different database users for different applications and functions. A read-only screen should not inherit signup, write, DDL, or administrator rights.

Views & procedures

Expose only required rows and fields. Where appropriate, grant execute on reviewed procedures rather than direct table access.

Restrict the OS account

The DBMS service must not run as root/system. Restrict file paths, network egress, and dangerous extensions.

Passwords

Store unique salted, slow password hashes—not reversible passwords. Password reset replaces a credential; it never emails the old one.

Financial data

Minimize storage, follow PCI DSS where applicable, use approved authenticated encryption, and keep keys outside the database.

Retention

Archive or delete unneeded sensitive data. Data that no longer exists cannot be taken in a future breach.

Understand systems,
not signatures.

The book closes with a durable lesson: advanced attacks may be slow and subtle, and injection is only one family of interpreter-boundary failures. Secure engineering requires understanding how the whole data flow works, researching the exact datastore in use, and reviewing assumptions that known-vulnerability scans cannot test.
